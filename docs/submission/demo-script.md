## Recording checklist

- Use **one continuous project/story**: the displayed website, candidate, script and output must actually belong together. Do not present SubSchool footage as a ReadyScore result.
- Prepare the completed ReadyScore result first, then record its genuine earlier steps. Use visible “generation time omitted” or “time jump” captions for waiting periods. Do not imply a multi-minute generation happened instantly.
- Use a strong audience-specific candidate, not a generic example. Show enough source content that viewers can see why it supports the chosen angle.
- Show actual native audio briefly, with music absent or very quiet. Start with the result; do not spend the first minute on registration.
- Show only a genuinely completed publication. If no ReadyScore post is available, show the queued job and call it **queued**, not published. A real YouTube example is enough; do not imply Instagram/TikTok validation you have not performed.
- For feedback, distinguish observed metrics from preference memory. No invented uplift, customers, views, or “viral” results.
- Hide personal email, balance if desired, bearer tokens, API keys, authorization codes, and private URLs. Do not expose an administrator session or offer it to judges.
- Use English narration, or English subtitles if narrating in another language. Keep the final public YouTube/Vimeo video at or below three minutes; verify it plays logged out.
- Put the live site and repository in the video description. Leave a few seconds of timing margin. The demo should **demonstrate** implementation, product coherence, a specific audience benefit, and the research-to-production idea—not recite judging criteria.
